
## 三、吃东西

```php
private function useItem(Connection $c, int $itemId): void
{
    $food = self::FOOD[$itemId] ?? 0;
    if ($food <= 0) return;

    // 必须核对手上真有这个物品（客户端会一直发包）
    $held = $c->inventory[36 + $c->heldSlot] ?? null;
    if (!is_array($held) || (int) $held['id'] !== $itemId) return;

    if ($c->food >= 20) return;                 // 饱了就不吃

    $now = microtime(true);
    if ($now < $c->nextEatAt) return;           // 一口 1.6 秒
    $c->nextEatAt = $now + 1.6;

    $slot = 36 + $c->heldSlot;
    // …扣物品、发背包…

    $c->food = min(20, $c->food + $food);
    $mod = self::FOOD_SAT[$itemId] ?? 0.6;
    $c->saturation = min((float) $c->food, $c->saturation + $food * $mod * 2.0);

    $this->syncVitals($c);
    $this->log("  {$c->username} 吃了方块{$itemId}，饱食度 {$c->food}，血 {$c->health}");
}
```

历史上这里曾有 `$c->health = min(20, $c->health + 1)`，已删除。
**但用户日志里仍出现「吃完血量 +1」**（见第五节），说明还有别的入口在改血量。

## 四、消耗与结算（唯一的两个入口）

### 4.1 消耗入口

```php
private function addExhaustion(Connection $c, float $amount): void
{
    if ($c->gamemode === 1) return;             // 创造不消耗

    $c->exhaustion += $amount;

    // 原版是 > 4.0（严格大于）
    while ($c->exhaustion > 4.0) {
        $c->exhaustion -= 4.0;
        if ($c->saturation > 0) {
            $c->saturation = max(0.0, $c->saturation - 1.0);
        } elseif ($c->food > 0) {
            $c->food--;
            $this->log("  {$c->username} 饱食度降到 {$c->food}");
        } else {
            break;
        }
        $this->syncVitals($c);
    }
}
```

调用点只有三处：

```php
// 1) 移动（move() 里）
$dist = sqrt((x-lastX)^2 + (z-lastZ)^2);
$this->addExhaustion($c, $dist * 0.01);        // 原版走路 0.01/格

// 2) 跳跃
$this->addExhaustion($c, 0.2);                 // 原版普通跳跃 0.2

// 3) 挨打
$this->addExhaustion($c, 0.3);                 // ← 注意：原版 0.3 是「攻击」消耗
```

### 4.2 结算入口（每 4 秒一次，不是每 tick）

```php
private function tickFood(float $now): void
{
    foreach ($this->players() as $f) {
        if ($f->gamemode === 1) continue;

        if ($now - $f->lastFoodTick < 4.0) continue;   // 80 tick = 4 秒
        $f->lastFoodTick = $now;

        if ($f->food >= 18 && $f->health > 0 && $f->health < 20.0) {
            $f->health = min(20.0, $f->health + 1.0);
            $this->syncVitals($f);
            $this->addExhaustion($f, 3.0);
        } elseif ($f->food <= 0 && $f->health > 1.0) {
            $this->damage($f, 1);                      // 饿伤
        }
    }
}
```

主循环里按这个顺序调用：

```php
$this->processDrops();
$this->tickXpOrbs();
$this->tickArrows($now);
$this->tickFood($now);        // ← 就是这里
$this->tickFluids($now);
$this->tickFurnaces($now);
$this->tickBrewing($now);
```

### 4.3 同步（0x06）

```php
private function syncVitals(Connection $c, bool $force = false): void
{
    $hungry = $c->saturation <= 0.0;
    if (!$force
        && $c->lastHealth === $c->health
        && $c->lastFood === $c->food
        && $c->wasHungry === $hungry) {
        return;
    }
    $c->send(0x06, float($c->health), varint($c->food), float($c->saturation));
    $c->lastHealth = $c->health;
    $c->lastFood   = $c->food;
    $c->wasHungry  = $hungry;
}
```

**全项目已经没有任何地方绕过它直接发 0x06**（原先是 6 处，已统一）。

## 六、已知与原版的差异（逐项）

| 项目 | 我们的实现 | 原版 1.8.9 | 影响 |
|---|---|---|---|
| 结算频率 | 固定 4 秒一次 | 每 tick 判断，`foodTimer >= 80` | 等价，但条件不满足时我们**不重置计时器**（原版会重置） |
| 计时器 | `lastFoodTick`（时间戳） | `foodTimer`（int 计数） | 行为近似 |
| 和平难度 | **完全没实现** | Peaceful 每 10 tick 回 1 饱食度、每 20 tick 回 1 血 | Easy 下不适用，但缺少分支 |
| `naturalRegeneration` 规则 | **没实现** | 必须为 true 才回血 | 我们无条件回血 |
| 饱食度恢复入口 | 只有 `useItem` | 同上 + Peaceful 分支 | 若饥饿条自己涨，说明存在未发现的写入点 |
| 挨打消耗 | 0.3 | 原版 0.3 是**攻击**消耗，挨打不扣 | 数值用错位置 |
| 疾跑消耗 | 未区分（全按走路 0.01） | 疾跑 0.1/格 | 疾跑时消耗偏小 |
| `prevFoodLevel` | 没有 | 有，用于客户端动画 | 影响饥饿条抖动 |
| 饱和度上限 | `min(food, …)` | 同 | ✓ |

## 七、需要帮忙定位的两个问题

### 问题 A：饥饿条「自己恢复」

Easy 难度下，站着不动、不吃东西，饥饿条会自己涨到满。

已确认：
- `useItem` 需要手上有对应物品，且 `nextEatAt` 1.6 秒限流
- `addExhaustion` 只减不加
- `tickFood` 只改 health，不改 food
- 没有 Peaceful 分支

**所以必然存在第四处写入 `$c->food`。** 但目前全项目搜索 `$c->food` 只有：
`useItem`、`addExhaustion`、`tickFood`（读）、`join`（从存档读）、`syncVitals`（读）。

### 问题 B：饥饿条满（20）但血量不恢复

`tickFood` 的条件是 `food >= 18 && health < 20`，Easy 难度、health ≈ 18、food = 20，
理论上每 4 秒应该 +1。

两种可能：
1. `tickFood` 实际没跑到（被前面的 tick 提前 return？）
2. 服务端的 `health` 已经是 20，客户端显示 18（同步问题）

**需要一份「每 4 秒打印 food/saturation/health」的日志**才能确定 —— 已经实现，
游戏内 `/foodlog` 打开即可：

```
[食物] Rain_0vO 结算：饱食 20 饱和 5.0 血 18.0
[食物] Rain_0vO 回血 +1 -> 19.0
```

或

```
[食物] Rain_0vO 结算：饱食 20 饱和 5.0 血 20.0     ← 服务端认为满血
```
