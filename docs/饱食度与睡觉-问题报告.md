## 二、饱食度：实现与三个 bug（已修）

### 2.1 当前模型

```php
// 消耗度攒满 4 扣一次：先扣饱和度，饱和度为 0 再扣饱食度
private function addExhaustion(Connection $c, float $amount): void {
    if ($c->gamemode === 1) return;               // 创造不消耗
    $c->exhaustion += $amount;
    while ($c->exhaustion >= 4.0) {
        $c->exhaustion -= 4.0;
        if ($c->saturation > 0) $c->saturation = max(0.0, $c->saturation - 1.0);
        elseif ($c->food > 0)   $c->food--;
        else break;
        $c->send(0x06, float($c->health), varint($c->food), float($c->saturation));
    }
}

// 每 4 秒结算一次
private function tickFood(float $now): void {
    foreach ($this->players() as $f) {
        if ($f->gamemode === 1) continue;
        if ($now - $f->lastFoodTick < 4.0) continue;
        $f->lastFoodTick = $now;
        if ($f->food >= 18 && $f->health > 0 && $f->health < 20.0) {
            $f->health = min(20.0, $f->health + 1.0);      // 回血
            $f->send(0x06, float($f->health), varint($f->food), float($f->saturation));
            $this->addExhaustion($f, 3.0);                 // 回血本身也消耗
        } elseif ($f->food <= 0 && $f->health > 1.0) {
            $this->damage($f, 1);                          // 饿伤
        }
    }
}
```

消耗来源：走路 `0.1/格`、受伤 `0.3`、跳 `0.05`、回血 `3.0`。

### 2.2 曾经出现的现象（现已修复）

| 现象 | 根因 |
|---|---|
| 吃任何东西都回 1 点血 | `useItem()` 里多写了一行 `$c->health = min(20, $c->health + 1)` |
| 饥饿条「掉得很快又自己恢复」 | `0x06` 的饱和度字段有 **4 处写死 `float(5.0)`**，每次发包客户端都看到饱和度 5 |
| 饱食度满了也不回血 | 自然回血有**两套**（`tickFood` 一套 + 旧 `foreach` 一套），两个计时器互相干扰 |

### 2.3 仍需确认

1. 现在吃东西只补饱食度和饱和度（`saturation += food * 1.2`），**这个 1.2 倍是估算**，原版是按食物逐个配表（苹果 2.4、面包 6.0、牛排 12.8…）。是否应该改成逐项表？
2. 客户端饥饿条出现「半个鸡腿」的中间态，是否只由 `饱和度 < 饱食度` 导致？我们的 `0x06` 每 4 秒才发一次，会不会不够频繁导致客户端显示滞后？
3. 创造模式我们还保留了 `food = 20` 不变，但客户端在创造下饥饿条是隐藏的 —— 有没有必要发 `0x06`？

## 三、睡觉：躺下能，起来起不来（未解决）

### 3.1 现状

```php
// 右键床（夜晚）
$bedPos = pack('J', (($x&0x3FFFFFF)<<38) | (($y&0xFFF)<<26) | ($z&0x3FFFFFF));
foreach ($players as $p) $p->send(0x0A, varint($playerEid) . $bedPos);
```

现象：客户端**进入躺姿**（画面变暗、看到自己躺下、出现「起床」按钮），但：

- 点「起床」按钮 → 客户端发 `0x0B action=2`，服务端收到并回了位置包 + 0x0A(-1)，**人还是躺着**
- 服务端定时唤醒（3 秒后设时间=1 + 位置包 y+0.1）→ 同样无效
- 结果：人永久卡在躺姿，只能重连

### 3.2 已经试过、都无效的

```
1. 发 0x0A，位置 = (-1,-1,-1)      → 无反应
2. 发 0x06 位置包，y + 0.1          → 无反应
3. 发 0x06 位置包，y 大幅偏移（±2）  → 无反应
4. 把床方块删掉                     → 无反应
5. 停止发任何包，等客户端超时        → 客户端不超时，一直躺着
```

### 3.3 参考实现的做法（别人的/phpmc，PHP 写的另一个服务端）

```php
// 右键床
sendPacket($cid, 0x0A, writeVarInt($eid) . writePosition($footX,$footY,$footZ));
$sleepingPlayers[$cid] = true;

// 所有人入睡后
$this->worldTime = 1;
foreach ($sleepingPlayers as $sid => $_) {
    $pos = $this->playerPositions[$sid];
    $y = $pos->y + 0.1;
    sendPacket($sid, 0x08, writeDouble($x).writeDouble($y).writeDouble($z)
                          .writeFloat($yaw).writeFloat($pitch).chr(0));
}
```

注意：他们的 `0x08` 在我们 1.8.9 里是 **Player Position And Look**（0x08），我们也是发这个。
**但这份参考代码在单人环境下没被验证过**（`required = 在线人数`，单人时 `currentSleeping(1) >= required(1)` 立即触发，作者可能没测）。

### 3.4 想请教的问题

1. **1.8.9 服务端到底用什么包能让客户端退出躺姿？** 是不是根本不是位置包，而是某个我们漏掉的包（比如 `0x0A` 的特定取值、或 `0x2C`/`0x47` 之类的世界事件）？
2. 客户端 `EntityPlayerSP.wakeUpPlayer()` 的触发条件是什么？在反编译里应该看哪个方法？
3. 如果 1.8.9 单人服务端做不到「正常起床」，业界通行做法是不是**干脆不发 0x0A**（右键床直接跳过夜晚）？
